## 1. 执行原则

- 三批全部属于本轮计划，不因分批而削减 B 类扩展。
- 不重做已确认的卡片→单弹窗界面；不改变现有七个角色和授权默认值。
- 先统一保存协议，再实现策略生命周期和恢复；不能给不同接口分别打不一致的补丁。
- 写代码前核实所需 DSH Service/Event/Config 契约；未核实的事件名、持久化方式不得当作既定方案。
- 实现保持单写者；测试作者仅写测试，独立审查只读，验证者只执行门禁。角色划分不要求启用 Agent Teams。
- 候选冻结后审查和验证；修复后重新冻结，只重跑受影响及最终必要门禁。记录 RED、GREEN、回归、最终门禁的不同证据。
- 不在所需子任务运行中重载插件；Host 变更按稳定入口维护规则重启生效，重启前确认维护窗口。
- 不手改托管配置，不擅自清数据、重置策略或扩权；备份和回退方案先于迁移。

## 6. 核心故障测试矩阵

| 场景 | 必须证明的结果 |
|---|---|
| 外部预设经旧接口/全量策略提交 | 服务端拒绝，零写入 |
| 授权池、定义、策略任一修订号过期 | 预校验能发现时零写入；边界并发变化有明确分项结果 |
| 定义创建成功、策略写入失败 | 不意外启用旧策略，可查询恢复 |
| 停用成功、删除失败 | 保持停用，不自动恢复授权 |
| 同 ID 重建或复制目标存在遗留策略 | 不静默继承授权 |
| 启动准备/创建期间撤权或停用 | 按确定启动边界拒绝，资源正确释放 |
| 请求重复、响应丢失、用户刷新 | 不重复创建/扩权，可恢复到可核对状态 |
| 恢复前另一会话修改或撤权 | 冲突可见，不覆盖新值、不恢复已撤权限 |
| 持久化失败、进程异常退出、旧 schema | 错误可见，状态不伪造，迁移与恢复有界 |
| 缓存命中期间撤权 | 授权检查仍立即生效 |
| 缓存旧请求晚于新请求返回 | 旧结果不能覆盖新目录 |
| 排序后刷新与重启 | 原生和管理页按同一规则保留顺序 |
| 实际打包与全量门禁 | 必需文件齐全、本机资料排除、任一故障返回非零 |

### T02 统一保存协议和服务端所有权 — 已完成（对应 F01–F05）

修改范围：新增 `save-protocol.js`（所有权、变更行、预校验、幂等、类型化错误）；重写 `settings-api.js` 的写入路径；`management-api.js` 新增 `plan()` 只读预校验；`client.js` 发送 `operationId` 并按错误码识别冲突。

已落实的行为：

- 服务端强制归属：非本插件预设只能被降级为无授权行，任何授予/扩大权限的改动都被拒（`forbidden`），零写入。
- 退役两个绕过联合保存的旧写入端点（全量策略保存、仅定义保存），只保留统一保存路径。
- 写入前完成全部预校验：归属、定义可写性、定义与策略目标一致、模型/强度、全部修订号（授权池修订号必填）。
- 只对**发生变化**的策略行重新做上下文校验，因此既有的失效/遗留行不再阻塞无关的深度或授权修改。
- 保存请求可带 `operationId`：相同负载重放已记录结果，不同负载以 400 拒绝；新增 `POST /operation` 查询已记录结果，供“结果未知”后的核对。
- 错误带 `code`（`validation` / `conflict` / `forbidden` / `unknown`），协议级拒绝为 400，业务拒绝仍为 200 分项报告。

证据（本机、workspace-write 沙箱）：`node scripts/check.mjs` → 36 个模块语法检查、21 项冻结哈希校验通过；`node --test-reporter=tap scripts/test.mjs` → `# tests 140 / pass 140 / fail 0`，退出码 0（基线 121，新增 19：`test/save-protocol.test.js` 9 项、`test/agent-save.test.js` 由 11 增至 21）。

环境限制与对门禁的修正：当前沙箱拒绝 `node --test`（每个测试文件派生子进程，`spawn EPERM`），因此新增 `scripts/test.mjs` 在单一进程内导入全部测试文件，`npm test`/`npm run verify` 改用它；原派生方式保留为 `npm run test:spawn`。此为门禁可重复执行（D03）的必要修正，不是绕过测试。

局限：`operationId` 记录在进程内存中，仅覆盖同一次保存的重复投递，不覆盖重启；T02 未做独立审查与真实浏览器/重启验收，批次一尚未交付。下一步：T03 删除/重建/复制生命周期。

### T03 删除、重建和复制生命周期 — 已完成（对应 A02–A04、U02）

- 删除由服务端派生策略，不接受客户端提交：先让该预设的派遣失效（原子写入策略行），**再**删除定义；任一步失败都不会留下可被派遣的预设。
- 如果静态允许列表（`allowedPresets`）仍包含该 ID，删除后保留一条**显式停用**行而不是直接移除，避免回退到允许列表。
- 新建与复制必须在同一请求初始化派遣策略，因此复用 ID 时不会继承遗留行的授权；遗留行仍可在全局弹窗中识别与清理。
- 复制模式放开 ID 编辑（此前固定为 `原ID-copy`），已有预设的 ID 仍不可改。
- 删除、重建与派遣准备共用同一把协调锁与修订号校验。

### T08 模型目录缓存 — 已实现并通过单元与集成验证

已核实的契约：`dsh-llm` 在适配器变更时**确实发布** `llm/adapters-updated`（`lib/index.js` 与 `invariant.js` 都有发布/监听），因此事件失效是真实接入而非猜测；有效期仍作为兜底。

实现（新增 `catalog-cache.js`）：
