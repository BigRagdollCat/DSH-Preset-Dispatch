# Agent 管理：上下文精简与子代理信息展示需求

状态：实施中。接口调查和 v0.6.0 基线测试已完成；阶段 A 候选已编写并进入测试修正；阶段 B 正在实现；阶段 C 已编写缺失行为测试，尚未实现。真实 Host/GUI 验收未完成。

适用插件：`@local/dsh-preset-dispatch`。代码基线：v0.6.0；接口调查基线：本机 DSH 0.2.0-rc.2。

配套文档：[工作清单](<09-context-and-dispatch-visibility-worklist.md>)。现有能力见 [README](<../README.md>)；上一轮需求见 [历史优化需求](<03-optimization-requirements.md>)。本文不撤销上一轮安全、保存、所有权与 UI 约束。

## 1. 用户目标与范围

1. 减少普通对话中反复携带的派遣提示，不隐藏派遣能力的发现入口。
2. 在准备派遣时查询角色职责、调度规则、模型授权和能力。
3. 查询已使用后，让后续模型请求仅携带短摘要，完整原始记录仍可审计。
4. 在主对话的派遣工具调用行显示 Agent 预设、模型和思考强度。
5. 进入本插件创建的子代理会话后，在输入框左下角显示同样的信息。

本文记录需求，不作为功能验收证明。实施由用户后续授权；各阶段测试、运行验收和发布状态分别记录，不以源码完成代替运行验收。

## 3. 上下文需求

| ID | 需求 | 验收条件 |
|---|---|---|
| C01 | 常驻仅保留派遣入口与关键边界 | 不常驻完整角色说明、完整模型池、固定模型推荐和交接细则；主代理仍能发现 `preset_list` 与 `preset_dispatch` |
| C02 | 默认查询只给派遣必需信息 | 返回可派遣角色、职责边界、必要调度规则、公共授权模型池及每角色差异限制；禁用/损坏预设不作为可用项 |
| C03 | 全量诊断显式请求 | 诊断模式保留全部预设、不可用原因、目录错误及未授权模型，不默认输出 |
| C04 | 查询有稳定关联标识 | 每次成功查询返回 catalogId；标识绑定当前父会话，不是授权票据；旧派遣调用不带标识仍可使用但不自动压缩 |
| C05 | 完整查询先供模型使用 | 只处理成功的默认查询；关联派遣必须来自查询结果之后的模型步骤；同一步查询/派遣不能证明已读取 |
| C06 | 已使用查询可替换为短摘要 | 关联子代理实际启动确认后，下一安全请求边界替换目标结果；不得在结果刚生成时立即替换 |
| C07 | 原始日志与工具配对保留 | 追加替换而非删除/篡改原事件；保留工具调用 ID 与消息身份，不删除 assistant/tool-call；不影响并行其他调用 |
| C08 | 不裁剪工作结果与错误 | 不裁剪 `preset_dispatch`、`job_output` 的工作结果，不裁剪查询错误、派遣错误、取消与拒绝信息；显式诊断结果不自动处理 |
| C09 | 摘要保留当前任务关键边界 | 说明目录已使用、已压缩、再次选择需查询；保留最终验收与不绕过拒绝等约束，不把旧授权快照当作当前权限 |
| C10 | 安全与恢复不依赖插件内存 | 从已有会话事件计算状态；重启、分支、官方压缩之后不会重复替换或误处理；关联不明确时跳过 |
| C11 | 压缩可关闭且兼容降级 | 默认关闭，实际接口/事件/适配器验证后启用；不支持或失败只停压缩，不影响原派遣和授权 |
| C12 | 用实际成本证明收益 | 分别测普通对话、查询决策、派遣后、再次派遣的输入量、缓存、费用与耗时；不能仅凭字符数宣称节省 |

### 3.1 常驻文案候选

> 需要分工时，先调用 preset_list 查询可派遣角色及规则，再使用 preset_dispatch。主代理负责最终验收，不得绕过授权或拒绝。

这是候选文案，不是已经替换的运行时提示。工具说明与参数规则各表达一次，不把删除的长文搬进工具 schema。

### 3.2 推荐生命周期

```text
成功查询默认目录
  → 模型在后续步骤提交关联派遣
  → 服务端实时授权复核、子代理实际启动确认
  → 下一获准进入的安全请求边界
  → 原查询结果替换为短摘要
```

“后台返回 jobId”不等于“子代理已启动”。启动判定及其可恢复证据须在实现前确定，不能只依赖一个内存布尔值。

### 3.3 边界处理

- 查询后未派遣：不按时间删除。再次派遣需取当前策略，不能依靠压缩摘要授权。
- 多次查询：按 catalogId 独立跟踪，不把新查询当成旧查询处理。
- 并行关联派遣：在相关调用启动判定完成后才处理；首版遇到拒绝、取消或失败时保留查询。
- 已被官方压缩遮蔽、关联不明、目标已不在当前模型可见节点中：跳过。
- 裁剪计量与替换为多条追加，不宣称原子事务；中间失败必须可检测，不重复扣减或产生损坏配对。
- 普通插件卸载不删除日志。关闭压缩只停止未来替换，不自动还原已替换的模型上下文。

## 4. 子代理信息展示需求

“派遣卡片”指主对话里的 `preset_dispatch` 工具调用行，不是设置页的 Agent 预设卡片。

| ID | 需求 | 验收条件 |
|---|---|---|
| V01 | 主对话注册专用派遣卡片 | preparing/start/result 各阶段可显示；不替换其他工具、不丢失错误和结果展开能力 |
| V02 | 显示预设身份 | 名称、稳定 ID、派遣时版本；保存名称与版本快照，后来重命名不改旧记录 |
| V03 | 区分计划与实际配置 | 首次请求前标记“计划/待确认”；实际 provider/model/effort 取自子会话已提交请求记录，不能把请求入参当成实际值 |
| V04 | 思考强度不猜测 | 显式指定、预设默认、父代理继承、适配器默认来源分开；未披露具体默认值时显示“模型默认，具体值未披露” |
| V05 | 进入子代理后左下角可见 | 在 `conversation.input.left` 追加只读信息，仅显示本插件创建的子会话；窄屏可缩短并展开详情，不覆盖权限/模型/提交控件 |
| V06 | 无输入框预览也能识别 | 先核实预览头部的真实插槽与 props；可用时显示同信息，不擅自替换整个会话组件 |
| V07 | 对话卡片、子会话与调用记录一致 | 使用稳定运行 ID/callId/jobId/childSessionId 关联，不用 label 或数组位置猜测；不把后台返回误标运行成功 |
| V08 | 状态与后续配置变化可见 | 显示待启动/运行/完成/失败/拒绝/取消/中断；记录可验证的实际配置变化，不承诺读取到提供方未披露的内部参数 |
| V09 | 不增加模型上下文负担 | UI 通过会话投影/界面数据更新，不为了展示追加提示词或重复大段工具结果；不轮询模型、不要求主代理额外调用查询 |
| V10 | 旧数据与恢复诚实显示 | 旧记录缺少实际值时标“历史配置，未核实实际请求”；不推断、删除或伪造旧值；恢复后仍能读到快照 |
| V11 | 从派遣卡片进入子代理会话 | 已确认子会话编号后，卡片提供“进入子会话”和“在侧边栏打开”入口；使用官方 `ctx.uiWorkspace.openSession(编号)` 与 `ctx.sidebarRight.openResource('dsh-resource://subagentchat/session/编号')`；一次性子代理按官方只读记录打开；编号未确认或服务缺失时不显示入口并说明原因，不用标签或数组位置猜测 |

## 5. 数据与接口约束

1. 区分 plannedRouting 与 observedRouting；当前 routing 返回契约不直接破坏，新增字段/格式须有兼容说明。
2. 保存派遣时预设快照、父会话/工具调用/运行/后台作业/子会话关联；子会话创建即建立关联，不等结束。
3. 历史存储字段、白名单与 schema 同步扩展；旧记录保持可读。是否需要提升存储域版本及迁移，由真实 storageDomain 契约决定。
4. 实际配置来自 `request/header`、`request/context` 等已提交记录；这些字段表示宿主使用的配置，不保证提供方的内部默认已知。
5. 每个会话的状态优先使用 sessionProjections 增量计算；订阅与注册随插件/agent 生命周期释放，不反复扫描全日志。
6. 不注册未知自定义日志事件类型。复用已有事件必须符合真实 schema；启动证据和恢复关联无法表达时，应报告限制，不能写私有字段凑数。
7. 历史仍仅保存必要元数据，不新增任务、回答、推理正文或凭证。查看/订阅关联子会话数据仍检查父子关系和访问权限。

## 6. 非目标与保留约束

- 不改官方 Skills，不把派遣规则做成新 Skill，不修改第三方 `subagent_role` 通道。
- 不修改七个角色职责、工具权限、默认模型/强度或现有授权池。
- 不重做卡片→独立弹窗的预设管理，不允许编辑外部预设。
- 实时授权、锁定、深度、安全服务身份检查均保留；catalogId 不绕过这些检查。
- 不修改 DSH 官方安装目录，不手改 profile 托管配置，不删日志/历史、不自动扩权。
- 不承诺零 Token、零缓存代价、所有 0.2.x 版本兼容或未披露默认强度可识别。

## 7. 分阶段发布与剩余验证

阶段 A：精简提示和默认查询；阶段 B：派遣卡片、子会话左下角与历史实际配置；阶段 C：查询使用后压缩。A/B 可先交付，C 在本机 Flash/Codex 实测通过前关闭，不因分阶段而移出需求范围。

尚未验证：真实钩子时序、多条追加的中间故障、Codex 续接/缓存、并行与取消、重启/分支/官方压缩组合、左下角布局、无输入框预览入口。

Host 变更需重启当前 DSH 进程；仅浏览器刷新不能加载新 Host 代码。重启、安装、清理、真实派遣消耗与发布需遵守届时权限及用户确认，文档记录不等于授权这些操作。
