# Agent 管理：升级、回退与需求覆盖

状态：T12 交付物。本文记录发布版本、兼容范围、数据 schema、升级与回退流程、**明确不支持的路径**，以及逐条需求覆盖。凡未真实验证的项目都在「未验证」中列明，不写作已完成。

## 1. 发布版本与兼容范围

| 项目 | 值 |
|---|---|
| 插件版本 | `@local/dsh-preset-dispatch` **0.6.0**（上一发布 0.5.0） |
| 兼容 Harness | `peerDependencies: @deepseek-ai/dsh: 0.2.0-rc.2`（运行时实测 `0.2.0-rc.2`） |
| 运行形态 | 纯 ESM、零运行时依赖；从 Host 入口解析 `zod`、`@deepseek-ai/dsh-storage-domain` 等由 Harness 提供的包 |
| 持久化依赖 | `storage` 服务的 `domain` 形态（由 `@deepseek-ai/dsh-storage-domain` 提供）；不可用时历史退化为内存并上报原因 |

0.6.0 相对 0.5.0 的行为变化（升级前需知）：

1. **服务端强制"只有本插件管理的预设可被操作"**：外部预设的策略只能被降级为无授权行；两个绕过联合保存的旧写入端点（全量策略保存、仅定义保存）已退役。仍在使用旧端点的脚本会收到 401/400。
2. **删除改为安全顺序**：先让该预设的派遣失效，再删除定义；删除失败不会留下可派遣的预设。
3. **新建/复制必须先中性化遗留行**，且必须在同一请求初始化派遣策略。
4. **派遣在真正创建子代理前会复核授权**，准备期间撤权会被拒绝（拒绝时释放刚创建的子代理）。
5. **保存结果新增分项契约**（`requested`/`completed`/`pending`/`finishedAt`）与 `operationId` 幂等；部分失败会暂停编辑，需「提交未完成部分」或「重新读取」。
6. **预设排序写入原生 `config.order`**；页面按它排序。首次移动会把重复的位置值展开为 10/20/30…。
7. 新增历史持久化与模型目录缓存（对使用者透明）。

## 2. 数据 schema 清单与兼容性

| 数据 | 位置 | 0.6.0 新增 | 旧数据如何被接受 |
|---|---|---|---|
| 插件设置 | Settings 命名空间 `local-preset-dispatch` | 无新键 | `presetPolicies[]` 逐行读取；缺 `modelScope` 的行按**实际生效值**归一化（有 `allowedModels` 即 `selected`，否则 `host`），因此显示与保存都不会改变语义 |
| 受管预设组 | configEditor 组 `agent-managed-presets` 的 `@deepseek-ai/dsh-agent-preset` 行 | 行 `config.order`、定义 `definition.order` | 缺 `order` 的行按 **20** 处理；`definitionRow` 写回时带上该字段 |
| 派遣历史 | storage domain `preset_dispatch_history`（域名只允许 `[a-z][a-z0-9_]*`，连字符会被运行时拒绝）（version 1，`layout:'per-record'`，`invalidRecords:'backup-and-skip'`） | 全新 | 0.5.0 不打开该 domain；0.6.0 首次打开时若不存在则创建 |
| Host 模型授权池 | Settings 命名空间 `subagent-model-selection-settings` | 无变化 | 本插件只读写 `enabled`/`allowedModels`，未改变其结构 |

**没有破坏性迁移**：所有新增字段都有默认值，读取路径对缺失字段做了归一化，因此"迁移中断"不可能损坏已有配置——最坏情况是某个新字段缺失，被按默认值解释。历史 domain 对无法通过 schema 的记录采用 `backup-and-skip`（后端把该记录文档移开并记录原因），因此一条坏记录不会让整个历史不可读。

## 3. 升级流程

1. **备份**（见 §4）。
2. 通过 DSH `plugin_manager` 重新安装 bundle（本包无依赖、无安装脚本，不需要 `pnpm`）。
3. **重启 DSH**：Host 模块按 URL 缓存，稳定入口 `entry.js` 只在进程重启时重新读取；仅切换 bundle 只会重新加载 Client 半边。
4. 刷新浏览器页面以加载新的 Client 字节（本环境没有 `dev:web` watcher，不承诺无刷新更新）。
5. 升级后自检：`npm run verify`（语法+冻结哈希 / 测试 / 真实打包），并在设置面板确认七个角色的名称、工具模板、派遣策略与默认模型未变。

**重要（运行实例与磁盘代码不同步）**：在**重启之前**，正在运行的实例仍执行旧代码——0.6.0 的所有安全改动（服务端所有权、删除顺序、启动复核、分项契约、排序、持久化、缓存）**尚未生效**。只切换 bundle 不会重新导入 Host 模块（模块按 URL 缓存）。因此不要把"已升级"理解为"已生效"。

## 4. 备份与回退

备份（升级前，按序执行）：

- profile patch：`C:\Users\<用户名>\.dsh\profiles\web\cordis.patch.yml`（含受管预设组与插件设置）
- 历史 domain 的存储单元：`C:\Users\<用户名>\.dsh\storages\` 下与本插件相关的单元（首次升级时可能尚不存在）
- 本次维护已留存一份清理前快照：`.maintenance-agent-debt/profile-before.yml`（**仅作参考**，它是 0.5.0 之前的清理前状态，不是 0.6.0 的升级前备份）

回退：

**先说明一个已核实的事实**：本工作区不是 git 仓库，且已安装的插件目录是指向工作区的**符号链接**，因此**磁盘上不存在 0.5.0 的文件副本**（已核实：无任何 backup/snapshot 目录）。也就是说"回退到 0.5.0"在当前状态下**不可执行**——0.5.0 的字节已经不存在，回退只能依赖使用者自己事前的备份。

自 0.6.0 起改为可执行的流程：发布候选已留存一份校验过的快照

- 快照位置：`.maintenance-agent-debt/snapshots/0.6.0/`，内含 `SNAPSHOT.txt` 记录**冻结表指纹** `0ce3de5938151c5d`（45 行）
- 回退步骤：
  1. 把该快照的内容覆盖回插件目录（保持目录名不变）；
  2. 恢复备份的 profile patch；
  3. 重启 DSH 并刷新页面；
  4. 用 `node scripts/check.mjs` 校验冻结哈希——不一致说明快照不完整，不要继续。
- **如何判断快照是否过期（重要）**：只跑快照自己的 `check.mjs` **不够**——一份过期的快照只要内部自洽就会通过，从而让回退静默丢掉后续修复（本文件先前就发生过：快照停留在第 11 轮，而候选已推进到第 15 轮，两者版本号却都是 0.6.0）。判据是**指纹**：用同样方式提取工作区 README 的冻结表并计算指纹，与 `SNAPSHOT.txt` 中的值比较；不同即表示快照已过期，必须重新留存后再谈回退。
- 以后每次发布都应先按同样方式留存快照（并更新指纹），否则回退仍然不可执行。

回退**不会**删除 0.6.0 写入的历史 domain：旧版本不读取它，因此它只是留在存储目录中的未使用单元；如需彻底清除，请在确认不再需要历史后手动删除该单元（本插件不提供跨版本的数据删除命令）。

**明确不支持的路径**：

- 不支持在不重启 DSH 的情况下让 Host 侧改动生效（这是设计约束，不是缺陷）。
- 不支持把**高于当前版本**写入的 domain schema 降级读取：`per-record` 后端会丢弃版本不被接受的记录文档，而不是尝试迁移；因此"新版本写入 → 旧版本读取历史"不受支持。
- 不支持在存在活跃子会话时删除预设（会被拒绝）。
- 不支持在 `storage` domain 不可用时保留历史：此时历史只在内存中，重启即丢失，页面会显示 `storageError` 原因。

## 5. 迁移演练

| 场景 | 演练方式 | 结果 |
|---|---|---|
| 旧设置行缺 `modelScope` | `test/policy.test.js` 的归一化用例 | 显示与保存都采用实际生效值，语义不变 |
| 旧预设行缺 `order` | `test/managed-presets.test.js` 的平局展开用例 | 读作 20；首次移动展开为 10/20/30…，不改变相对位置 |
| 记录不满足 schema | domain 声明 `invalidRecords:'backup-and-skip'` | 坏记录被移开并记录原因，历史仍可读 |
| 重启后仍有 `running` 记录 | `test/history-store.test.js` 的 `restore` 用例 | 改为 `interrupted` 并把更正写回介质 |
| 迁移中断（写入一半） | 无需演练：新增字段均有默认值，读取路径归一化 | 不会损坏既有配置 |

**未验证**：以上都是单元/契约层面的演练。**真实介质上的"写入 → 重启 → 恢复"往返、以及真实 domain 的首次创建**必须在完整 DSH 重启后确认（T13）。真实回退演练也尚未执行——本环境无法在不影响用户会话的情况下切换插件版本。
