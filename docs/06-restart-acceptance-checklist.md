# 重启验收清单（T13 剩余项）

本清单用于在**完整重启 DSH 后**确认那些无法用单元测试替代的项目。逐项给出观察点与预期；任何一项不符，请把「实际现象」记下来，不要先改配置。

## 0. 重启前（建议先备份）

- profile patch：`C:\Users\<用户名>\.dsh\profiles\web\cordis.patch.yml`
- 历史存储单元：`C:\Users\<用户名>\.dsh\storages\` 下与本插件相关的单元（首次升级时可能还不存在）
- 说明：`.maintenance-agent-debt/profile-before.yml` 是**清理前快照**，不是本次升级前备份，不要拿它回退。

## 1. 重启与刷新

1. 重启 DSH（Host 模块按 URL 缓存，只有重启才会加载新 Host 代码）。
2. 浏览器**刷新**页面（Client 字节在激活时缓存）。
3. **机械判定"新代码是否真的生效"**（不要靠肉眼）：在插件目录执行

   ```
   node scripts/live-probe.mjs
   ```

   它探测运行实例上的路由：只存在于 0.6.0 的路由（历史查询、目录刷新）应回答 `400 Authenticated operator request required`（= 路由存在），已退役的旧端点应回答 `401`（= 路径未知）。
   - 预期输出：`verdict: the 0.6.0 Host code IS live`
   - 若显示 `NOT live yet`：重启没有真正完成，先解决这一点，后面的验收都不必做。
   - 重启**之前**运行它会得到 `NOT live yet`——这是正常的，也正是它能分辨新旧代码的证明。
4. 预期：设置面板出现「Agent 管理」分区，卡片为原生风格网格（不是裸 HTML 列表）。

## 3. 历史持久化真实往返（H01/H03/H04）

1. 用「子代理派遣」派遣一个角色（例如 verifier）并等它结束。
2. 打开「调用记录」：应有该次记录，状态为完成。
3. **重启 DSH**，刷新页面，再次打开「调用记录」。
4. 预期：记录**仍在**；若某次派遣被中断（进程在运行中重启），它应显示 `interrupted`（而不是仍在运行）。
5. 若记录为空：查看该弹窗是否显示 `storageError` 文案——它说明历史只在内存中，原因是 storage domain 未能打开；请把该文案原样反馈。

## 4. 原生列表顺序一致（O02）

1. 在管理页对某个角色点上移（↑）或下移（↓）。
2. 刷新页面：管理页顺序保持。
3. 打开 DSH 原生的 Agent 预设选择器（新建会话时的预设列表）。
4. 预期：两处顺序按同一规则（`config.order`）排列；位于首/末的卡片，其对应方向按钮为禁用状态。

## 5. 真实浏览器交互（U03、R01）

- 浅色与深色主题下，卡片、弹窗、按钮对比度正常。
- 点击卡片打开**一个**弹窗（同时含「预设设置」与「子代理派遣设置」），Esc 关闭、Tab 在弹窗内循环。
- 编辑名称后**不要保存**，刷新页面：应出现未完成草稿的恢复提示（「上次保存未全部完成」或「已恢复未完成的草稿」），主保存按钮保持禁用，需点「提交未完成部分」或「重新读取」。
- 勾选一个「需授权」的模型：保存被拦截，直到勾选「同时启用 DSH 全局模型授权」。

## 6. 门禁复跑

在插件目录执行：

```
node scripts/check.mjs        # 预期：41 模块语法 / 45 行冻结哈希 / 45 必需项，exit 0
node scripts/test.mjs         # 预期：全套通过，exit 0
node scripts/pack-check.mjs   # 预期：46 个文件将发布，exit 0
```

（等价于 `npm run verify`，但在本沙箱里 `npm` 的 PowerShell shim 不可用，因此直接跑 node。）
